🖱️ 双网关统一域名 · GUI 点击操作流程

全程点网页 / 点界面，不用 SSH，不用输入任何命令。涵盖 OpenWrt LuCI、Cloudflare Dashboard、飞牛 OS。
路线图： ① 前置检查 → ② Cloudflare DNS → ③ OpenWrt 防火墙 → ④ OpenWrt DDNS → ⑤ OpenWrt hebing 包 → ⑥ Cloudflare Tunnel → ⑦ NAS FPK → ⑧ 端到端验证

前置检查 & 准备

0.2 确认 IPv6 通（LuCI 里点两下）

LuCI
  • 打开浏览器 → http://192.168.1.1（换成你的路由器 IP）登录
  • 左侧菜单 网络 → 接口
  • 看 WAN6 那一行，"IPv6 地址"一栏应该有一个 240e:: / 2a08:: 开头的公网 IPv6，不是 fd 开头（ULA）
  • 左侧菜单 网络 → 诊断 → 诊断工具选 Ping → Ping 主机填 2400:3200::1（Cloudflare 的 IPv6 DNS）→ 点测试
✅ 丢包 0% 就是 IPv6 通了。如果全超时，打运营商电话给光猫改桥接。

Cloudflare · DNS 记录

Cloudflare Dashboard

在 Cloudflare 网页端操作：

  • 登录 https://dash.cloudflare.com → 点进你的域名
  • 左侧 DNS → Records → 点 Add record
  • TypeAAAA
    Namea
    Content随便填一个占位 v6，例如 240e::1（后面 DDNS 会自动改）
    Proxy status⚪ DNS only（灰云图标）
    TTL1 min
  • 点 Save
⚠️ AAAA 记录一定要灰云（DNS only），别开橙云。开了 v6 直连就废掉了。

保存后，先别管 A 记录 —— 等后面第 6 步配置 Cloudflare Tunnel 时它会自动帮你生成。

OpenWrt · 放行 IPv6 防火墙

LuCI
  • 左侧 网络 → 防火墙 → 滚到页面底部 端口转发 下面的 自定义规则 区域（不同版本位置略有差异），或者直接在 通信规则 标签页点 添加
  • 名称Allow-NAS-FPK-v6
    协议tcp
    源区域wan
    目标区域lan
    目标端口8443
    动作接受
    IPv6勾上（有些版本有独立的"IPv6 规则"选项卡，也在那里加一条）
  • 勾上启用 → 点 保存并应用
有些 OpenWrt 版本（23.05+ fw4）在"通信规则"里直接有 IPv4/IPv6 分栏，IPv6 那栏也要加一条一模一样的。

OpenWrt · 配置 DDNS（让 AAAA 记录自动更新）

LuCI

4.1 先装 DDNS 组件

  • 左侧 系统 → 软件包 → 点一下 更新列表（刷新一下包索引）
  • 右上角搜索框输入 ddns → 分别找到 luci-app-ddns 和 ddns-scripts_cloudflare.com-v4 → 各自点 安装
  • 等安装完，刷新左侧菜单，应该出现一个新的 服务 → DDNS

4.2 新建一条 Cloudflare 服务

  • 左侧 服务 → 动态 DNS → 点 添加新服务
  • 启用✓ 勾上
    服务提供商Cloudflare.com-v4
    主机名a.c.xxx
    用户名anything（随便填，CF token 模式忽略）
    密码填 Cloudflare API Token（下面讲怎么生成）
    IP 地址源网络接口
    网络接口wan6
    IPv6 操作✓ 勾上（关键！DDNS 脚本只更新 AAAA 需要这个）
    检查间隔60（秒）
  • 点 保存并应用

4.3 生成 Cloudflare API Token

Cloudflare Dashboard
  • 登录 Cloudflare Dashboard → 右上角头像 → 我的档案（My Profile） → API Tokens → 创建 Token
  • 模板选 Edit zone DNS，Scope 里只勾 你的那个域名
  • 其他默认 → 生成 → 立即复制保存（只显示一次！）

4.4 把 Token 填回 DDNS 的密码栏

LuCI
  • 回到 服务 → 动态 DNS，点那条服务的 编辑
  • 把刚才生成的 Cloudflare API Token 粘到 密码 框里
  • 保存并应用

4.5 看 DDNS 是否在跑

  • 在 DDNS 服务列表页面，那条服务的状态应该显示 ● 已运行
  • 右侧有个查看日志链接，点开应该能看到：updated to new IPv6 240e:3b2:...::88 这样的成功日志
✅ 验证：去 Cloudflare DNS Records 页面刷新一下，AAAA 记录的值应该自动变成路由器的公网 v6 了。

OpenWrt · 安装 hebing 包

LuCI
⚠️ hebing_0.1.0-1_x86_64.ipk 现在装的是脚手架自带的 mock 二进制，用来验证打包流程没问题。生产部署请替换为真实 hebing 二进制再跑 build-ipk.sh 重新打一次。

5.1 先把 .ipk 弄到路由器能访问的地方

LuCI 的软件包页面支持 本地文件上传，所以最简单：

  • 本地电脑打开 dist/openwrt/ 文件夹，找到 hebing_0.1.0-1_x86_64.ipk

5.2 上传安装

  • 左侧 系统 → 软件包
  • 页面滚到底部，找到 上传软件包 区域（有的版本在右下角）
  • 点 选择文件 → 选刚才那个 .ipk
  • 点 上传并安装
  • 弹出的确认框点 确定
  • 看到 安装成功 就 OK 了

5.3 确认 hebing 在运行

  • 左侧 服务 → 应该能看到 hebing（如果没菜单，就去 系统 → 启动项 找）
  • 状态应该是 ● 运行中，旁边有 重启 / 停止 / 启用 / 禁用 按钮
  • 如果在启动项页面，找 "hebing" 那行，已启用 那里应该有勾，运行中 也有勾

5.4 改 hebing 监听端口（配合 Cloudflare Tunnel）

hebing 要监听 CF Tunnel 指向的端口。假设我们统一用 7999：

  • 左侧 服务 → hebing → 高级设置 标签（或者直接 系统 → UCI 配置 搜 hebing）
  • 把 listen_port 改成 7999
  • 保存并应用 → 页面上点一下 重启 按钮

Cloudflare · Zero Trust Tunnel

Cloudflare Zero Trust

这步创建 v4 穿透隧道，让没有 IPv6 的客户端也能连进来。

6.1 创建隧道

  • 浏览器打开 https://one.dash.cloudflare.com → 登录
  • 左侧 Networks → Tunnels → 点 Create a tunnel
  • 隧道类型选 Cloudflared
  • 名字填 hebing-v4-fallback（随便起）→ 下一步
  • 看到一个大命令框，类似： 
    cloudflared service install eyJhbGciOiJSUzI1NiJ9...（很长很长）
    直接复制那段 token 部分（eyJ... 开头的那串），保存好。命令本身我们不在路由器上跑。

6.2 配置隧道指向 hebing

  • 在隧道详情页（刚创建完会自动跳到），点 Public Hostnames → Add a public hostname
  • Subdomaina
    Domainc.xxx
    TypeHTTP
    URLlocalhost:7999
  • 点 Save hostname

6.3 安装 cloudflared 到 OpenWrt 并启动隧道

LuCI
  • 左侧 系统 → 软件包 → 搜索 cloudflared → 安装 cloudflared（核心程序）和 luci-app-cloudflared（可选，有界面）
  • 如果装了 luci-app-cloudflared：左侧菜单出现 服务 → Cloudflare Tunnel → 新建实例，把刚才的 token 粘进去 → 启用
  • 如果只装了 cloudflared：用 LuCI 的 系统 → 启动项 → 新建一个 init 脚本（或者用 系统 → 调度任务 加一条开机自启）：
    如果实在不想碰命令，最简单的做法：回到 Zero Trust 隧道详情页，Cloudflare 提供了一个 Run in Cloudflare 选项 —— 让 cloudflared 跑在 Cloudflare 的服务器上，你只要回源到 hebing 就行。这样 OpenWrt 上完全不用装 cloudflared。
✅ 回到 Cloudflare DNS Records 页面，应该已经看到 A 记录自动生成了：A a 192.0.2.1 橙云 Proxied。AAAA 是灰云，A 是橙云，完美。

飞牛 NAS · FPK 入口容器

飞牛 OS
  • 浏览器打开飞牛 OS：http://NAS的IP → 登录
  • 左侧 应用中心 → 搜索 Docker 或 容器管理 → 如果没装先装一下
  • 装完进 容器管理 → 点右上角 Compose → 新建 compose 项目
  • 项目名填 fpk-entry，Compose 文件框里粘贴： 
    services:
  fpk:
    image: your-registry/fpk:latest   # 换成你实际的镜像
    container_name: fpk-entry
    restart: unless-stopped
    ports:
      - "8443:443"
      - "8080:80"
    volumes:
      - ./data:/var/lib/fpk
      - ./certs:/etc/ssl/fpk
    environment:
      - TZ=Asia/Shanghai
  • 点 保存并启动
  • 回到容器列表，看到 FPK 容器状态 ● 运行中

端到端验证（全程浏览器）

本地浏览器

8.1 验证 v6 直连（主路径）

  • 打开浏览器隐身窗口（避免缓存干扰）
  • 地址栏输入 https://a.c.xxx → 回车
  • Chrome 按 F12 打开 DevTools → Network 标签 → 刷新页面
  • 点第一条请求 → Timing 标签 → 看 Connect 时间
    Connect < 20ms → 走的 v6 直连 ✨ 太棒了

8.2 验证 v4 CF 穿透（兜底路径）

  • Mac 临时关掉 IPv6：系统设置 → 网络 → Wi-Fi/以太网 → 详情 → TCP/IP → 配置 IPv6 选 关闭 → 好
  • 等 3 秒 → 回到浏览器隐身窗口重新打开 https://a.c.xxx
  • DevTools → Network → Timing
    Connect 50~200ms，且响应头里有 server: cloudflare → 走的 CF 穿透 ✅
  • 测完记得回去把 IPv6 打开

常见故障（也不用 SSH 查）

🔴 DDNS 显示报错 / 日志里说 "invalid credentials"

CF API Token 过期或者没 DNS:Edit 权限。CF → My Profile → API Tokens → 重新生成一个，Scope 选 Edit zone DNS → 复制回 LuCI DDNS 密码栏保存即可。

🔴 Zero Trust 隧道一直 Offline

说明 cloudflared 客户端没连上。最简单的方案：去 Zero Trust 隧道 → Settings → 把 Tunnel 类型改成 Cloudflare (previously named "cloudflared") 的"Cloudflare 托管"模式，让 CF 自己跑，你只要回源 URL 指向 OpenWrt 的 hebing 就行。OpenWrt 上完全不用装 cloudflared。

🔴 浏览器打开 a.c.xxx 超时

  1. 先看看 IPv6 防火墙规则在不在（LuCI → 网络 → 防火墙 → 通信规则）
  2. hebing 服务有没有在跑（LuCI → 服务 → hebing）
  3. 端口对不对（UCI 配置里 hebing 的 listen_port = CF Tunnel URL 里写的 localhost 端口）

🔴 hebing 装不上 / 装完秒退

LuCI → 系统 → 软件包 → 搜索 hebing 看装没装上。然后看 系统 → 日志，过滤 hebing，一般是端口被占了或者配置文件格式错了。
